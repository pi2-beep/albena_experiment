# Експеримент Албена — уеб приложение

Flask приложение за провеждане на изследването „ИИ и формирането на преценка при публични политики“. Проектът е подготвен за безплатния план на Render и не използва база данни, CDN или външни скриптове.

Интерфейсът следва официалната визуална идентичност на Института по публична администрация. Пълноцветното лого и фигуралният знак са локални копия на актуалните файлове от [официалния сайт на ИПА](https://www.ipa.government.bg/) и се зареждат от `static/img/` без външна заявка при работа на приложението.

## Реализиран поток

1. Вход с анонимен код на участника.
2. Описание на проекта.
3. Информирано съгласие с пет задължителни декларации.
4. Прочит на казуса и доказателствата.
5. Самостоятелна преценка без ИИ.
6. Работа с ИИ с 3 задължителни и 2 незадължителни взаимодействия.
7. Преценка след ИИ, оценка на влиянието, проверка и окончателно решение.
8. Въпроси за професионалния опит с генеративен ИИ.
9. Преглед и изтегляне на един PDF с всички предоставени данни.

Самостоятелната преценка се заключва при преминаване към работата с ИИ. Във всяка от двете оценки точките за варианти A, B и C трябва да имат сбор точно 100.

Сесията има максимална продължителност 45 минути от входа. Таймерът е видим през цялото време, а през последните 60 секунди интерфейсът преминава в червен предупредителен режим. При изтичане формулярът се заключва и наличните данни могат да бъдат експортирани и архивирани дори ако не са попълнени всички полета.

Постоянният бутон „Заданието“ отваря казуса и доказателствата върху текущата стъпка. „Запази копие и излез“ записва черновата в `localStorage`, изтегля JSON копие на устройството и приключва сървърната сесия. При повторен вход със същия код браузърната чернова може да бъде възстановена.

## Съхранение

- Сървърната сесия се съхранява като JSON в `data/sessions/`.
- Браузърът пази резервна чернова в `localStorage` според кода на участника.
- Генерираният PDF се записва временно в `data/pdfs/`, изпраща се заедно с JSON копие към конфигуриран FTPS архив и веднага се изтегля.
- Не се записват име, имейл или друг пряк идентификатор.

Важно: файловата система на безплатна Render услуга е временна. FTPS архивът пази завършените PDF и JSON файлове независимо от рестартирането на Render. Участникът пак изтегля лично PDF копие в края. Браузърната чернова остава само на същото устройство и в същия браузър.

FTP архивирането се включва с `RESULTS_ARCHIVE_BACKEND=ftp`. Необходимите настройки са `RESULTS_FTP_HOST`, `RESULTS_FTP_PORT`, `RESULTS_FTP_USERNAME`, `RESULTS_FTP_PASSWORD` и `RESULTS_FTP_DIRECTORY`. По подразбиране се използват TLS и пасивен режим чрез `RESULTS_FTP_TLS=true` и `RESULTS_FTP_PASSIVE=true`. При хостинг с IP/alias за връзката и различно валидно име в TLS сертификата се задава и `RESULTS_FTP_TLS_SERVER_NAME`.

Паролата се задава единствено като защитена променлива в Render и не се записва в Git. Обикновен FTP без TLS може да се разреши с `RESULTS_FTP_TLS=false`, но не се препоръчва, защото данните и паролата се предават некриптирано. Старият GitHub архив остава наличен като резервна реализация при `RESULTS_ARCHIVE_BACKEND=github`.

## Локално стартиране

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Отворете `http://127.0.0.1:5000`.

## Тестове

```bash
pip install pypdf
python -m unittest discover -s tests -v
```

Тестовете проверяват:

- входа и възстановяването на сесия;
- задължителните взаимодействия 1–3;
- сдвоените полета за незадължителните взаимодействия 4–5;
- сбора от 100 точки;
- отказа за PDF при непълен формуляр;
- кирилицата и основните секции в PDF.

## Публикуване в Render

### Вариант 1 — Blueprint

1. Качете папката в GitHub хранилище.
2. В Render изберете **New → Blueprint**.
3. Свържете хранилището.
4. Render ще прочете `render.yaml` и ще създаде безплатна Python web услуга.

### Вариант 2 — ръчна настройка

- Runtime: `Python 3`
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn app:app`
- Health check: `/health`
- Environment variable: `SECRET_KEY` със случайна дълга стойност
- Secret environment variable: `RESULTS_GITHUB_REPOSITORY`, например `owner/private-results-repository`
- Secret environment variable: `RESULTS_GITHUB_SSH_KEY` с частния write deploy key за архива

За FTPS задайте вместо тях:

- `RESULTS_ARCHIVE_BACKEND=ftp`
- `RESULTS_FTP_HOST`, `RESULTS_FTP_PORT`, `RESULTS_FTP_USERNAME`, `RESULTS_FTP_PASSWORD`
- `RESULTS_FTP_DIRECTORY=/albena-results`
- `RESULTS_FTP_TLS=true`, при нужда `RESULTS_FTP_TLS_SERVER_NAME`, и `RESULTS_FTP_PASSIVE=true`

## Структура

```text

templates/index.html   стъпков формуляр
static/app.js          логика, валидация и автозапазване
static/styles.css      адаптивен дизайн без външни ресурси
fonts/                 локални шрифтове за PDF
data/                  временни JSON и PDF файлове

tests/                 автоматични тестове
```
